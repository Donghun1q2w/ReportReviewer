# page-aligner 모델 선정 벤치마크 — opus 4.8 / Sonnet / Haiku 4.5 (2026-07-09)

**결론: `page-aligner`는 claude-opus-4-8로 확정.** 하위 모델은 가격 우위에도 불구하고 방향 감지 자체가 성립하지 않아 탈락.

## 방법

- **대상**: PU2601233-2-MTC.pdf 73페이지 (페이지별 0°/90° 혼재 실입력 — 메타데이터 /Rotate 전부 0, 스캔 내용 자체가 회전).
- **GT 확정**: 오케스트레이터가 컨택트시트 7장 전수 판독 + 대표 13페이지를 CW90/CW270 양방향 몽타주로 픽셀 실측(전부 CW90 정립, CW270 상하반전) → 73페이지 회전각 확정. **GT: 90°=51p (p1–29, p32–51, p54, p56), 0°=22p.**
- **블라인드 A/B**: 동일 시트·동일 지침(agents/page-aligner.md 절차)·동일 출력 스키마로 3개 모델을 병렬 위임. GT·기대 분포는 미제공. 출력: `<stem>_orientation__{opus,sonnet,haiku}.json`.
- **채점**: 페이지 단위 회전각 일치율 (scratchpad/score_orient_models.py, 결정적 diff).

- 선정 기준(계획 Rev.1): "오분류 0인 최저가 모델, 전 모델 오분류 시 최고 정확도 모델" → 3모델 모두 오분류 존재 → 최고 정확도 opus 채택.
- **안전 실패 설계의 검증**: opus의 오분류 3건은 모두 agents/page-aligner.md의 보수적 폴백(불확실→0+uncertain 보고) 경로였다. 오케스트레이터가 uncertain 페이지를 픽셀 재확인해 90으로 확정·정렬했고(운영 절차 그대로), 최종 E2E에서 73/73 페이지 정방향을 달성했다. 반면 sonnet의 270° 오판은 플래그 없이 확신 출력 — 하위 모델은 정확도뿐 아니라 **오류 양상 자체가 위험**하다.
- 비용: haiku < sonnet < opus 순으로 저렴하나, 30% 정확도(=무작위 미만, 다수 클래스 찍기 수준)에서는 가격이 무의미. 감지 비용 자체가 케이스당 시트 ~N/12장 Read + 위임 1회로 이미 작다.
